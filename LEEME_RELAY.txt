----------------------------------------------------------------
 COMO SE USA (3 pasos)
----------------------------------------------------------------

1) PONER TU CUENTA. Opcion A (rapida): abre
   betterserver-oss\Config.json y pon la contrasena de tu cuenta:

     "relay": {
         "enabled": true,
         "directory_host": "relaysc.dr2.site",
         "directory_port": 9001,
         "username": "s38bd8ef11f",
         "password": "AQUI_TU_CONTRASENA"
     }

   Opcion B: compilar_server.bat -> opcion 7 (Configurar RELAY),
   que te la pregunta y la guarda solo (tambien respalda el
   Config.json).

   NOTAS:
   - La cuenta NO se registra desde el server: usa la que ya
     creaste en la web de relaysc.dr2.site.
   - Si la contrasena queda vacia, el server arranca con el relay
     apagado y un solo aviso (no intenta conectar, no spamea).
   - Con el relay activo, "allow_duplicate_ip" tiene que estar en
     true (tu Config.json ya lo tiene; el configurador lo garantiza).

2) RECOMPILAR. compilar_server.bat -> opcion 1 (o 2 si queres
   desde cero). NO hace falta borrar el exe: si el server esta
   corriendo, el .bat te avisa y lo cierra el solo (Windows
   bloquea el archivo mientras corre, por eso antes fallaba el
   "Permission denied"/LNK1168 si lo dejabas abierto).

3) ARRANCAR Y VERIFICAR. Al iniciar el server vas a ver en el
   log (en la VENTANA GUI es el chat de siempre, mismo lugar que
   los mensajes de Amy Canon):

     Relay: connecting to directory at relaysc.dr2.site:9001...
     Relay: region <region> at <ip>:<puerto>
     Relay: online - players can join at <ip> ports X-Y   <- LISTO

   Los jugadores entran con IP:PUERTO (necesitan el cliente con
   el fix IP:PUERTO que ya aplicamos, o el parche PortFIX de
   penguinehis) a la IP del relay y el puerto X que dice el log.

   Si algo sale mal, el log te dice exactamente que pasa:
   - "wrong relay password for 's38bd8ef11f'"  -> contrasena mal
   - "the directory does not recognise '...'"  -> usuario mal o
     la cuenta no existe en ese puerto (prueba 9000 vs 9001)
   - "no answer from the directory at ..."     -> sin internet o
     el directorio esta caido
   - "no reply for 45s, reconnecting"          -> se cayo el
     tunel; reconecta solo

----------------------------------------------------------------
 DETALLES UTILES
----------------------------------------------------------------
- Cuando un jugador entra por el relay vas a ver:
    "Relay: session N -> local port P as <IP real del jugador>"
- Para el servidor, los jugadores del relay llegan desde
  127.0.0.1 (IP "sintetica", como el original). Los BANS por IP
  no sirven para releados (usa el ban por UDID, que si funciona);
  los OPERATORS por IP tampoco aplican a releados.
- El relay reconecta solo si se cae (reintenta cada 10 segundos).
- Para APAGAR el relay: "enabled": false en Config.json (o
  opcion 7 del .bat) y reinicia el server.
- El chat del JUEGO no muestra nada del relay: los avisos son
  solo para VOS en la ventana del server.
