QUE PASO (el error que me mandaste)
------------------------------------
ERROR in action number 1 of Draw Event for object obj_lobby:
Variable obj_lobby.spr_char_info_rouge(101880, ...) not set before
reading it at gml_Object_obj_lobby_Draw_0 (line 193).
"rouge no muestra su cartel especifico y al pasar de rouge a kris
lanza eso"

Dos bugs del botón "Escribir" del editor de placas (mi v54) se
combinaron:

BUG 1 — LA LINEA DEL REDIRECT ESTABA MAL INDEXADA (off-by-one).
El juego compara "sprInd", el índice 0-based de chars[] (Tails=0,
..., Rouge=14, Kris=15). El editor escribió
    else if (sprInd == CHARACTER_ROUGE)   (= 15)
    else if (sprInd == CHARACTER_KRIS)    (= 16)
Con 15, la línea de Rouge se dispara con KRIS seleccionado
(sprInd de Kris = 15 == 15) y ejecuta
draw_sprite(spr_char_info_rouge, ...) => CRASH "not set" al pasar
de Rouge a Kris, exactamente tu error. Rouge (sprInd 14) nunca
caía en su línea: veía la placa de Blaze (frame 14 crudo). Y la
línea de Kris le robaba el frame al killer EXE.

BUG 2 — EL SPRITE NUNCA SE REGISTRÓ EN EL .yyp.
El paso 3 del writer ("registro en el .yyp") usaba un buscador de
.yyp roto en modo "Abrir carpeta" (solo funcionaba en el modo solo
lectura): devolvía null, el registro fallaba con un aviso y el
sprite quedaba sin registrar => GameMaker lo compila como variable
no definida => el crash "not set". Por eso grep del .yyp daba 0.

LA REPARACION DEL JUEGO (estos archivos de TU repo)
---------------------------------------------------
1) objects/obj_lobby/Draw_0.gml — las 2 condiciones corregidas:
       else if (sprInd == 14) // CHARACTER_ROUGE (chars[14])
               draw_sprite(spr_char_info_rouge, ...)
       else if (sprInd == 15) // CHARACTER_KRIS (chars[15])
               draw_sprite(spr_char_info_kris, ...)
   Ahora Rouge ve SU placa, Kris ve la suya, y ningún killer pierde
   su frame. Tus 2 PNG de placa (los que hiciste) se usan tal cual.

2) Sonicexe The Disaster 2D Remake.yyp — los 2 sprites
   (spr_char_info_kris, spr_char_info_rouge) REGISTRADOS en
   "resources" (2530 -> 2532). Validado como JSON, sin duplicados.

3) Sonicexe The Disaster 2D Remake.resource_order — las 2 entradas
   agregadas junto a las de fw/sallycanon/vanilla.

Con solo copiar estos 3 archivos al proyecto y recompilar (F5),
el crash desaparece y ambos carteles salen.
