FIX v1 CRASH obj_player_warning ("Unable to find instance for object index 300")
================================================================================
(Solo CLIENTE — recompilar en GameMaker. El server NO se toca.)


EL SINTOMA
----------
- Crash en partida, repetible al terminar la ronda con el aviso de campar
  en pantalla:

  ERROR in action number 1
  of Draw Event for object obj_player_warning:
  Unable to find instance for object index 300
   at gml_Object_obj_player_warning_Draw_75 (line 4) -
   if(global.player.isDead || global.player.revivalTimes >= 2)

- Con eso el Draw GUI del aviso muere a mitad del fade y el juego escupe
  el error (en build con "abort on error" puede cortar la partida).


QUE ES EL OBJETO
----------------
- obj_player_warning es el aviso ANTI-CAMP: si un superviviente pasa 20 s
  sin cambiar de "chunk" de pantalla (tras el primer minuto de ronda),
  scr_move_basic:307 lo crea: textos de miedo en pantalla ("the fear of
  leaving the shelter has shackled you"...), scr_player_slow(5) y la
  musica bajada. Se apaga solo si te mueves de chunk, si pasas a estar
  muerto, si te quedas sin revivas (revivalTimes >= 2) o al cambiar de
  room.


LA CAUSA
--------
- La linea 4 del Draw GUI (Draw_75) lee global.player con DOT-ACCESS
  directo para auto-apagarse si el player murio. Eso funciona mientras
  global.player sea una instancia viva.
- El crash llega en el FRAME DE TRANSICION de fin de ronda: el codigo de
  red reescribe global.player ANTES de que el cambio de room (que aplica
  al FINAL del frame) destruya el aviso (persistent: false, muere con el
  room). Ese ultimo Draw lee un global.player que ya no resuelve a una
  instancia viva:
    * game over individual  -> global.player = noone (net_state_game
      3265 / 3418 / 3969 y net_tcpprocess:167)
    * vuelta a vote / lobby -> global.player = obj_exe, que es un INDICE
      DE OBJETO, no una instancia (net_state_vote:32, net_state_lobby:85
      y el default de scr_globals:9)
- Leer una variable de ahi = "Unable to find instance for object index
  300" (300 = el indice del objeto). El mismo sabor de error sale si la
  instancia del player fue destruida y el id quedo colgando.
- El aviso era el UNICO dot-access a global.player SIN guard de todo el
  proyecto (cero hermanos en los demas Draw events). El resto del juego
  ya se protege con el mismo patron: scr_player_hurt:195,
  scr_player_slow:3 (fix v4.8.1) y net_state_game:3253 (game over) usan
  instance_exists(global.player) antes de tocar la instancia.
- NOTA: la muerte NORMAL no destruye la instancia del player (scr_player
  _hurt la deja viva con isDead = true), por eso el aviso se apagaba
  bien casi siempre — hacia falta la transicion de ronda con el aviso
  todavia en pantalla.


EL FIX (1 archivo, +13/-2)
--------------------------
1) objects/obj_player_warning/Draw_75.gml
   - El check de "player muerto" pasa a usar el MISMO guard de la casa:

        if(!instance_exists(global.player))
                moved = true;
        else if(global.player.isDead || global.player.revivalTimes >= 2)
                moved = true;

   - Sin player vivo se toma el MISMO camino que "muerto": fade-out
     (0.016/frame) y autodestruccion limpia — el CleanUp sigue
     restaurando la musica.
   - La formula isDead/revivalTimes queda IDENTICA; el resto del evento
     esta byte a byte igual (Create, CleanUp, .yy, textos, terraria,
     timer).
   - La ultima linea del evento llama scr_player_slow(5), que ya tiene
     su propio guard (v4.8.1): sin player es no-op, no revienta.
